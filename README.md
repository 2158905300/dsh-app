# DeepSeek Harness 分享试验版 0.4.7-alpha

面向 ARM64、Android 11 及以上的单 APK 试验包。它把聊天界面、Termux 基础 bootstrap、首次环境安装向导、模型配置入口、相册/文件选择、无障碍手机工具与专用浏览器合在一个 App 里。首次安装会联网下载 Node、DSH 和编译依赖；这是在线初始化包，不是完全离线运行包。模型推理也需要联网和使用者自己的 API Key。

**目前未在干净安卓设备上完成首次安装验证。请先小范围测试，不要当作正式通用版本发布。**

## 应用内安装与使用指南

安装页顶部和聊天页都提供“使用指南”入口；权限页也能打开指南和安装诊断。指南是原生离线页面，不依赖联网、完成初始化或 DSH 服务，涵盖 12 个主题：安装准备、首次安装与进度、Key/模型、首次聊天、相册与文件、自己安装插件、手机控制、专用浏览器、后台恢复、常见错误、升级备份隐私以及试验版范围。可从指南直接打开系统权限设置和官方模型控制台。

安装页列出 7 个实际安装里程碑，显示当前步骤、活动指示、耗时和最近输出时间；不显示未经测量的下载百分比。诊断页默认暂停自动刷新，保留阅读位置，可手动刷新或主动开启两秒实时更新；内容未变时不重绘日志。可选择安装总日志或最近 12 份 npm 详细日志，显示最近约 96 KB，并提取/复制错误上下文。常见 Key、Bearer、连接 token、npm token 和 URL 凭据会被遮盖，但不能识别所有敏感信息，分享前仍须检查。查看帮助和日志不会主动停止安装。

## 给试用者

0.4.7 支持在内核明确不支持 Landlock 时，由设备使用者选择无沙箱模式继续。默认不降低限制：安装会先停止，安装页显示对应按钮，使用者阅读权限说明并再次确认后才继续。支持 Landlock 时仍完成工作区内允许、工作区外拒绝写入的功能验证；未知探测错误或功能验证失败仍停止，不提供自动跳过。无沙箱模式使用 `danger-full-access`，工具和插件可以访问本 App 有权访问的文件，包括配置和会话；没有 Android root 权限，不自动开启无障碍或手机控制。聊天页顶部持续标明运行模式。

如果旧版总日志中已记录到达安卓补丁阶段或明确的内核不支持错误，且 DSH 核心仍存在，重试从补丁阶段继续，重新检查 Node、文件锁、内核探测及运行入口，不重复 npm 安装。原依赖损坏时仍会失败，需结合日志修复。升级同一分享签名的 0.4.6 后，不需要卸载或清除数据；在失败安装页选择无沙箱继续并确认即可。该版本通过模拟测试和 APK 检查，仍需在朋友手机验证完整启动和对话。

保留 0.4.6 的长时间编译诊断修正：分别显示系统依赖、DSH 原生依赖、sharp 图片模块阶段；恢复 sharp 的正常编译输出。npm 下载和编译阶段总时限从 30 分钟延长到 60 分钟，达到总时限会明确停止，不会误当网络错误换源重编译。此时限不包含此前的系统包安装或之后的独立 sharp 编译，不是预计完成时间。总日志每约 5 MB 轮转一次，始终保留最近输出，避免大量警告填满日志后丢失最后的结果。这些修改不代表已确认具体手机的编译耗时或失败原因，也不提供断点续编译保证。

保留 0.4.5 针对访问 `registry.npmjs.org` 的 `ETIMEDOUT` 增加的独立“npm 下载源”选项。默认先尝试 npmmirror 再尝试 npm 官方源；每次先检查固定 DSH 版本是否可获取，再运行安装。安装中的网络超时、域名解析/连接错误可以触发换源，原生编译等非网络错误会停止并显示日志。模型 API Key 与公开 npm 软件包下载无关。

该选项与 Termux 系统软件源分开。选择镜像/官方时使用本次安装的独立 npm 配置，保持 HTTPS 校验，不改写使用者的 `~/.npmrc`；如依赖原有 npm 用户配置中的代理，可选“沿用现有 npm 配置”。下载缓存保留，所有源都失败时仍需检查网络。已验证两源元数据包含指定 DSH 版本，并通过模拟换源测试，尚待朋友手机验证。npm 源与超时配置依据 [npm 官方说明](https://docs.npmjs.com/cli/using-npm/config/)。

保留 0.4.4 的暂停日志更新、npm 详细日志选择、错误上下文和复制摘要。更新保留原日志；`A complete log of this run can be found in…` 只是日志路径，不是实际错误原因。

保留 0.4.3 针对 `CANNOT LINK EXECUTABLE node` / `OSSL_PROVIDER_add_conf_parameter` 的基础环境整体升级、OpenSSL 重新安装与失败依赖修复，以及安装 npm/DSH 前的 Node/OpenSSL 启动验证。中断安装导致的旧 node/npm 配置失败不会阻止后续基础库修复；修复或验证仍失败时明确停止，不会标记安装完成。清除继承的自定义动态库/Node 路径变量，避免错误库路径影响验证。已通过模拟旧库与配置失败测试，尚未在朋友手机上验证。

保留 0.4.2 的可选镜像、自动换源、每源约两分钟超时、严格索引错误检查、非交互安装和实时日志。Key 可以提前填写，运行环境完成后才能保存并启动。

1. 使用一台没有安装 Termux 或本项目旧版的 ARM64 安卓设备，安装 `DeepSeek-Harness-Share-0.4.7-alpha-arm64.apk`。
2. 打开 App，选择软件源后点击“安装运行环境”，默认依次尝试清华镜像和官方源。保持稳定联网并预留足够存储空间；依赖会在手机编译，可能耗时较长。安装有前台通知，不必另外安装 Termux 或 Shizuku。
3. 环境安装完成后，填写你自己的 DeepSeek API Key 和模型名称（默认 `deepseek-flash`），点击“保存并开始使用”。此步骤只保存配置，不会预先发送测试请求；实际可用性取决于账户和模型权限。
4. 需要操作手机/网页时，在 App 的“权限”页开启本地控制。读取和操作其他 App 界面还需手动开启“DeepSeek Harness 手机控制”无障碍服务。聊天不要求开启这些权限。
5. 附件入口可以选择相册图片或系统文件。断线后重新打开 App 会尝试启动服务。设置“无限制”电池策略有助于后台运行，但厂商清理和强制停止仍会中断进程。

**不要在已经安装原版 Termux 或旧 Harness 一体版的手机上卸载强装。** 本版仍使用 `com.termux` 包名和运行库固定目录，不能与它们共存；它使用新的私有分享证书，与之前的覆盖升级包不同，系统会拒绝直接更新。请保留原环境和数据。要迁移应另行备份和制定迁移方案。本包也不能直接使用其他签名的 Termux 附加应用。

## 数据、插件与权限

- APK 不包含开发者的 API Key、桥接令牌、聊天、附件、账号登录状态或手机备份。
- 模型 Key 在首次配置时写入本机 App 私有目录，页面不回显现有 Key、禁止页面截图，App 关闭系统备份。
- 默认 `workspace-write`，并编译、测试 Android Landlock 后才标记环境安装成功。仅在明确识别内核不支持且使用者通过原生对话框确认后，才允许无沙箱 `danger-full-access`；其他错误不自动降级。
- 运行时固定为 `@deepseek-ai/dsh@0.2.0-rc.2`，包含对应安卓补丁；其他系统软件包从 Termux 软件源安装。不要未经验证直接自升级核心，否则可能覆盖兼容补丁。
- 基础插件为 DSH 自带的基础/网页能力与本项目手机浏览器插件；手机界面工具通过 `phone` 命令和随附 skill 提供。没有把私人插件、语音服务、第三方视觉密钥或整套插件市场打入包中。
- 使用者自行在插件市场选择和配置其他插件；本包不会代填第三方服务密钥。插件的安卓兼容性需分别确认，依赖 Windows/桌面程序的插件不能保证可用。
- 工具桥接只监听 `127.0.0.1:3082`，使用本机生成的私有令牌。手机控制默认关闭。

## 失败和重试

网络或编译失败时，安装页会显示未完成。排除网络问题后点击重试，不要卸载或清除数据。详细安装日志在 App 私有目录，可用内置终端查看 `~/../harness-install.log`。日志只记录环境安装输出，不读取模型配置；分享诊断信息前仍应自行检查内容。

如果出现 `Some index files failed to download`，请先等待当前源失败或超时；自动模式会尝试另一个源。全部失败后可选择不同源重试，并检查网络和系统时间。镜像使用 HTTPS，APT 签名校验保持开启，不会绕过证书/签名错误来继续安装。可点“停止本次安装”，它只终止本次安装的独立进程组，保留已下载内容；下次安装会尝试恢复中断的软件包配置。

镜像地址依据 [Termux 官方镜像列表](https://github.com/termux/termux-packages/wiki/Mirrors) 与 [清华镜像帮助](https://mirrors.tuna.tsinghua.edu.cn/help/termux/)；`pkg` 的镜像检测行为见 [Termux 官方脚本](https://github.com/termux/termux-tools/blob/master/scripts/pkg.in)。本安装器使用限定到单次命令的 APT 源列表，不覆盖使用者已有的系统源文件。

`cannot locate symbol` 表示可执行程序与实际加载的库不匹配，也可能受错误动态库路径影响。Termux 是滚动更新环境，不支持只更新部分基础包；见 [官方执行环境说明](https://github.com/termux/termux-packages/wiki/Termux-execution-environment#dynamic-library-linking-errors)。本版在首次安装/未完成安装的重试中统一升级 App 内的 Termux 基础软件包，再安装依赖并验证 Node。不会修改其他 Android App；更新会改变本 App 内的基础软件包版本，耗时和下载量可能增加。

已经完成初始化后，再次安装同一分享签名的后续更新，应保留私有数据。请妥善保留开发者本地 `keystore/`，遗失签名密钥后不能再生成可直接覆盖升级的版本。签名密钥及其密码绝不能随源码或分享包分发。

## 已完成的验证与限制

Java 编译、安装脚本语法、APK 签名、资源/组件检查、安装资源白名单和凭据模式扫描，以及全新配置生成/重试保留设置测试由构建流程或本地验证执行。原 Termux dex、原生库和 bootstrap 资源应与官方输入保持一致，新增 UI 与安装代码单独放在 `classes30.dex`。

这些检查不等于实机安装成功。尚待干净设备验证：bootstrap 首次初始化、软件源可达性、所有原生模块编译、Landlock 内核支持、模型对话、相册附件、手机/浏览器工具、后台被清理后的恢复。当前包仅包含 ARM64 bootstrap，未验证其他架构或机型。没有 root，也没有 ADB/Shizuku 的系统 shell 提权。
